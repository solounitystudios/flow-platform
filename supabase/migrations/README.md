# Migrations

These 7 files are the exact SQL applied to the `flow-platform` Supabase project for the Connections and Messages work in this PR (verified against the live schema via `pg_get_functiondef`, `information_schema.columns`, and `pg_policy`). Migration history (`supabase migration list` equivalent): `20260818210949` through `20260818215030`.

**Known gap, out of this PR's scope:** the project's earlier schema (`profiles`, `skills`, `organizations`, `opportunities`, `applications`, `events`, `event_attendance`, `recommendations`, `verifications`, `flow_ledger`, `notifications`, `rewards`, `reward_redemptions`, `achievements`, `profile_achievements`, and the `passport_summary`/`reliability_breakdown` views) was built across 11 earlier migrations (`flow_core_v1` through `phase3_fix_search_path_warnings`) that predate this branch and were never captured as local files in any branch, including `main`. Reconstructing those accurately would mean reverse-engineering table/policy/function definitions from the live database rather than replaying real history, and risks producing files that look authoritative but don't actually match what was run. Rather than do that silently, it's flagged here as a pre-existing gap for a dedicated follow-up (ideally via `supabase db pull` against the live project, which does this correctly) — not something to paper over as part of a Connections/Messages PR.

Practical implication: running only these 7 files against a fresh database will fail (they reference `profiles`, `events`, `opportunities`, etc.). They're being tracked from here forward as the source of truth for schema changes; new work should add new files rather than going back to editing the live database directly without one.
